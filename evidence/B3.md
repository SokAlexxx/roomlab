# B3 — Телеметрія, E2E v1 і план якості (KAN-13)

## Дизайн
- `booking/telemetry.py`: middleware `RequestTelemetry` пише на логер `roomlab.request` один JSON-рядок на запит рівно з полями `time` (UTC, ISO 8601, мс), `operation` (метод + ім'я маршруту, напр. `POST bookings-create`; невідомий шлях — `unresolved`), `status`, `elapsed_ms` (`perf_counter`), `request_id`.
- `request_id`: клієнтський `X-Request-ID` приймається лише за шаблоном `[A-Za-z0-9._-]{1,64}`, інакше UUID4; повертається в заголовку відповіді. Виняток у view логується як 500 і передається далі.
- Облікові дані не логуються: немає заголовків, тіла, query string, шляху, імені користувача.
- `config/settings.py`: лише дописано один рядок у кінці `MIDDLEWARE += ["booking.telemetry.RequestTelemetry"]`; наявні рядки не змінено. Оскільки `LOGGING` не змінювався, модуль сам додає stderr-хендлер для сервісу; під `manage.py test` хендлер не додається (логи перевіряються через `assertLogs`).
- `docs/quality.md`: рівні перевірки, відповідність 5 початкових ризиків конкретним наявним тестам, стан цілей якості.

## Метод перевірки
- `booking/tests/test_e2e.py::V1EndToEnd` — реальні ендпоінти через Django test client на PostgreSQL без моків: alice створює (201) → бачить у `mine/` (bob — ні) → bob скасовує (403, рядок незмінний) → bob у той самий слот (409) → alice скасовує (200 `CANCELLED`, слот вільний у пошуку) → повторне створення (201, новий id). Також перевірено послідовність лог-рядків і унікальність `request_id`.
- `TelemetryLogging` / `TelemetryOnException`: точний набір полів, UTC-час, відсутність пароля/Basic-заголовка/імені/даних запиту в лозі, 401 і 404 логуються, безпечний `X-Request-ID` повторно використовується, небезпечний (ін'єкція JSON, задовгий, з пробілами) замінюється, виняток → 500.
- Виконано `py -3.12 .roomlab-check.py` (Docker-збірка, Ruff, Django check, `makemigrations --check`, migrate, повний набір тестів на PostgreSQL): `ROOMLAB_CHECK_OK`.

## Обмеження
- Stderr-хендлер сервісу в тестах не перевіряється (вимкнений під `manage.py test`); перевіряється вміст лог-записів.
- Лог не ротується й не агрегується; p95 і час відновлення автоматично не вимірюються — `elapsed_ms` лише дає сирі дані.
- Ризик 4 (legacy при міграції v2) покрито лише частково; тест знімку legacy-рядків з'явиться з v2.
- E2E охоплює лише v1; потоки v2 (PENDING, погодження) не входять.
