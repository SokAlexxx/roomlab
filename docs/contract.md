# RoomLab API
Local JSON API, Basic auth using booking.http.endpoint(method), request.user from the server. Seed R100 and R101, capacity 100 and 101, users alice, bob, admin. admin alone is_staff. Password from DEMO_PASS. Seed must be idempotent and preserve existing bookings. ISO 8601 explicit time zone. Use [start,end), adjacent reservations allowed. Room names unique. Responses for lists are plain JSON arrays. Errors use booking.http.error(code,status).
GET /api/rooms/available/?start=...&end=... -> 200 rooms {id,name,capacity}, ordered by id.
POST /api/bookings/ {room_id,start,end} -> 201 record {id,room_id,start,end,status}. 400 invalid_input (missing/bad, naive timestamp, start>=end); 404 not_found; 409 slot_conflict. v1 always ACTIVE. DB-level concurrent exclusion for same room with real PostgreSQL.
GET /api/bookings/mine/ -> 200 own records including inactive ones.
POST /api/bookings/{id}/cancel/ {} -> 200 CANCELLED. Other owner 403 forbidden. Missing 404; inactive 409 invalid_transition. Slot free immediately.
v2: capacity >100 gets PENDING; PENDING reserves the slot. Staff GET /api/approvals/ lists PENDING. Staff POST /api/approvals/{id}/decision/ {"decision":"approve"|"reject"} -> 200 ACTIVE|REJECTED; same repeat 200 with original audit, opposite repeat 409. Return decided_by, decided_at, decision in decision response. Owner can cancel PENDING. Track actor, time and outcome atomically; protect transitions from races. Legacy entries retain IDs and all prior data. No retroactive approval.
Data integrity: migration 0001 already defines Booking.Status (ACTIVE, CANCELLED, PENDING, REJECTED) and DB check constraints booking_start_before_end and booking_status_valid. Keep them; add new constraints to the same Meta.constraints list. Authentication: booking.http.basic_user caches a verified Basic header for 60 s (invalidated when the password hash changes), so latency measurements reflect the API, not PBKDF2. manage.py test uses the MD5 hasher for speed.
Local demo scope only. No signup, web UI, email, outside hosting or real data.
